# K230 ↔ ESP32 UART 协议

两块"大脑"之间的串口通信约定。**只走小数据（JSON），音频/视频绝不走 UART。**

## 物理层

| 项 | 值 |
|----|----|
| 接口 | UART (异步串口) |
| 波特率 | 115200 |
| 数据位/校验/停止 | 8 / None / 1 (8N1) |
| 逻辑电平 | 3.3V（两端一致，无需电平转换） |

### 接线（交叉 + 共地）

```
ESP32-S3                 K230 (庐山派)
  TX (GPIO17) ─────────→  RX
  RX (GPIO18) ←─────────  TX
  GND         ──────────  GND   ← 必须共地
```

> ⚠️ K230 端引脚以「庐山派官方原理图」为准，见 `k230/ai_robot/board.py` 的 `UART_*`。
> K230 的 UART0 是 REPL 控制台，**不要占用**，桥接用另一路 UART。

## 数据层：NDJSON（一行一条 JSON）

每条消息是**一行 JSON，以 `\n` 结尾**。这样接收端按换行切分即可，简单可靠。

- 单条消息建议 < 128 字节
- 字段尽量短（省带宽、好解析）
- 收到无法解析的行直接丢弃，不崩

### 通用字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `t`  | string | 消息类型（type），必填 |

---

### K230 → ESP32（视觉事件）

**人脸位置**
```json
{"t":"face","x":0.0,"n":1}
```
| 字段 | 范围 | 含义 |
|------|------|------|
| `x`  | -1.0 ~ +1.0 | 人脸中心水平位置：-1=最左, 0=正中, +1=最右 |
| `n`  | 整数 | 当前画面里的人脸数 |

> `x` 用归一化值（与摄像头分辨率无关），ESP32 直接拿去算舵机方向：
> `x>0` 向右转、`x<0` 向左转、`|x|` 越大转越快、接近 0 就停。

**没有人脸**
```json
{"t":"noface"}
```

---

### ESP32 → K230（状态/心跳，可选）

**心跳 / 探活**
```json
{"t":"ping"}
```
对方回：
```json
{"t":"pong"}
```

**机器人状态广播**（让视觉端知道当前在干嘛，按需用）
```json
{"t":"state","v":"listening"}
```
`v` 取值示例：`idle` / `listening` / `thinking` / `speaking`

---

## 联调顺序（先证明通道，再接真实数据）

1. **环回自测**：ESP32 把 TX 和 RX 用杜邦线短接，自己发自己收，确认驱动 OK。
2. **K230 → ESP32**：K230 每 500ms 发一条 `face`，ESP32 monitor 打出来。
3. **ESP32 → K230**：ESP32 发 `ping`，K230 收到回 `pong`。
4. 通了之后，再把 `face.x` 接到舵机/编码器闭环。
